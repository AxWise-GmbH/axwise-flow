# Native Goose efficiency build

Implemented the first three approved changes: efficient tool-selection policy v2, bounded batch reads, and post-edit snapshots. The source changes are synced to the original orqaly-goose checkout. AST/LSP query presets are deferred to a separate comparison, as planned; no OMP component was added.

- `hashline_edit action=read_many` accepts 1–16 paths with independent snapshots/errors and at most 256 KiB of serialized line data. Every digest covers the complete file. Existing single-file calls remain supported.
- Successful edits return up to 64 lines / 16 KiB of changed-region context, a fresh full digest and exact line anchors. Truncation and pagination are explicit. Failed safe edits return no post-edit snapshot.
- Native guarded writes retain full preimage and anchor checks. Rollback still preserves intervening modifications. Batch reads are not a shared filesystem transaction. Ordinary write/edit tools remain available and do not acquire these native guards merely because the flag is enabled.
- Policy v2 favors gathered context, reuse of valid snapshots/results, coherent multi-file changes, useful regression tests and relevant verification. It avoids routine extra LSP diagnostics after successful compiler checks. Both loops receive the policy only when native tools are mounted; feature-off instructions stay unchanged. No automatic test-success caching was added.
