Abstract

Abstract

This is a continuation—not a replacement—of the original Sparsity Nexus thesis. The 2025 paper asked whether principles from deterministic, cache-conscious structures such as Judy arrays could inform probabilistic neural attention. It proposed three branches: tree-based positional encodings, a Judy-indexed KV cache, and Judy-masked attention. A June 2026 update added compression and emerging sparse systems to that picture.

This report investigates whether a large language model’s addressable context can exceed its resident attention state by routing each query to a small KV working set distributed across unified memory and storage. It uses a fanless 24 GB M4 MacBook Air as a deliberately constrained reference platform, Qwen3.8-27B as the retrofit target, and Qwen3.8-Flash-Next as evidence that query-aware sparse attention can be integrated during model design.

Resource analysis shows that a heavily quantized 27B model may fit on the reference system while a dense one-million-token KV cache cannot. We therefore specify a hierarchy comprising a protected recent and pinned region, semantic candidate generation, a code-to-block directory, compressed cold storage, accelerator-side refinement, and adaptive fallback. Judy arrays are evaluated only as one possible directory representation.

This report does not claim a reproduced one-million-token Apple Silicon result. Its contributions are a calibrated hypothesis, a resource model, a related-work audit, and a reproducible protocol for measuring quality, prompt-ingestion cost, decode throughput, memory, storage traffic, and sustained thermal behavior.

Evidence-status statement

No Apple Silicon benchmark in this document demonstrates one-million-token operation, 11–12 output tokens per second, or near-reference quality. Those values are preregistered targets. Results cited from other projects apply only to their reported models, hardware, software, and evaluation settings.

Research lineage

The idea before the benchmark

The Sparsity Nexus did not begin as a MacBook optimization proposal. It began with a broader question: can the design philosophy of a classical, deterministic, cache-conscious data structure teach us anything useful about a learned, probabilistic attention mechanism? The original paper treated Judy arrays and attention as products of different computing eras and different hardware, then looked for transferable principles rather than a literal fusion.

Version 2.0 narrows one branch of that inquiry into a measurable routed-KV experiment. It does not retroactively erase the other branches or claim that the initial philosophical analogy was already an implementation.

June 2025 · origin

A Foundational Analysis

Compared deterministic Judy lookup with soft neural retrieval and proposed three hybrids: tree positional encodings, Judy-indexed KV, and Judy-masked attention.

June 2026 · major update

From analogy to related systems

Added compression as a third axis and compared the thesis with radix prefix caches, hierarchical pruning, sparse retrieval, and tree-to-matrix representations. Those were parallels—not proof that Judy itself had won.

August 2026 · v2.0

A falsifiable systems hypothesis

Narrows Judy to a candidate directory inside semantic KV routing, adds the 24 GB M4 Air constraint, and preregisters capacity, quality, bandwidth, and thermal tests.

The philosophical core: three kinds of “less”

Both Judy and sparse attention exploit emptiness, but they begin from philosophically different places. That distinction remains central to the paper.

Inherent, structural sparsity

A Judy array assumes most of a vast discrete key space is empty. Its adaptive representation stores the occupied structure compactly and changes node layout with density.

Induced, emergent sparsity

Attention starts from continuous similarity. A sparse pattern is learned, estimated, or imposed because only some historical tokens matter strongly for the current query.

Representational compression

Added explicitly in the June 2026 update: quantization makes each stored weight or KV value cheaper. It complements routing, which reduces how many values become active.

Dimension Judy array Neural attention The bridge proposed here
Lookup Hard, exact, deterministic membership or mapping. Soft, probabilistic relevance over continuous vectors. Use a semantic projection for recall, then a discrete directory for block and tier resolution.
Key space Discrete integers or byte strings with shared prefixes. Layer- and head-dependent query/key vectors. LSH, PQ, learned scores, or block summaries turn continuous relevance into searchable candidate codes.
Sparsity Known from occupied keys and represented structurally. Emerges from a query and can change at every layer. Keep a protected core, route a working set, and widen when uncertainty makes the sparse assumption unsafe.
Hardware objective Minimize pointer-chasing cost and CPU cache-line fills. Maximize dense parallel throughput and coalesced access. Let CPU-friendly irregular selection and GPU-friendly exact attention cooperate through a shared/tiered memory path.
Failure mode A poor key distribution or layout loses locality. A missed token can change an answer many steps later. Measure routing recall, miss traffic, adaptive widening, and fallback—not only lookup time.

How the original three proposals evolved

Original branch Initial idea Status in this revision
Tree-based positional encodings Encode structural or vocabulary-trie paths as an inductive bias rather than relying only on linear position. Preserved as a speculative research branch, but outside the 24 GB inference experiment. It would require model training and its own quality study.
Judy-indexed KV cache Project high-dimensional keys into discrete LSH/PQ codes and use a CPU-side Judy structure to resolve relevant KV. The main surviving branch. It has evolved into semantic candidate generation, a code-to-block/tier directory, compressed cold storage, exact reranking, and fallback.
Judy-masked attention Represent dynamic sparse attention masks using Judy-inspired bitmap/radix organization. Conceptually related to hierarchical and learned block-sparse routing, but a literal pointer-rich Judy implementation is not GPU/Metal-native and remains unproven.

Why the old hardware mismatch leads to the Air

The original paper emphasized a real mismatch: Judy trades more branching logic for fewer expensive CPU cache misses, while accelerators prefer regular, wide, coalesced work. A direct port of a pointer-heavy CPU structure is therefore not the thesis. The thesis is heterogeneous: irregular discovery on the side of the system that handles it well, followed by compact dense work on the accelerator.

Apple unified memory changes the transfer boundary but not the physics. CPU and GPU can address one pool without a conventional PCIe copy, yet they still share only 24 GB and 120 GB/s on the reference Air. That is why this consumer machine is the next chapter of the original hardware argument, not a different thesis.

“The path forward is not simple fusion, but inspired adaptation.”

The current protocol keeps that 2025 conclusion, while making one descendant precise enough to fail.

1 · Scope

Research question and claim boundaries

The central question is not whether a quantized 27B model can be loaded on a consumer laptop. It is whether the amount of context that model can accurately address can grow much faster than the KV state and attention work kept active for each generated token.

Can a Qwen-class transformer maintain a one-million-token logical memory while promoting only a small, query-dependent KV working set into the active path—and do so without hiding the cost in host RAM, SSD traffic, quality loss, or preprocessing?
Supported direction

Working-set routing

Multiple systems report query-aware KV selection, host offload, or learned block routing in their own settings.

Open implementation hypothesis

Judy as directory

No audited project establishes Judy as the best mapping from semantic codes to KV blocks or memory tiers.

Unverified target

The 24 GB Air result

One million logical tokens, near-reference quality, and 11–12 effective tok/s have not been reproduced here.

Why the consumer machine is scientifically useful

The fanless 24 GB M4 MacBook Air is chosen because it removes convenient escape routes. It has one finite CPU–GPU memory pool, no separate 100+ GB host-memory reservoir, and no active cooling to mask sustained power and thermal behavior. At the same time, its shared address space makes CPU-side irregular search and GPU-side dense computation plausible without a conventional PCIe copy. This combination turns a familiar consumer device into a strict test of the working-set thesis.

Unified memory is not free transfer. CPU routing, GPU model execution, KV reads, and page movement contend for the same capacity and bandwidth. A successful result must account for all of them.

3 · Resource model

What blocks one million tokens

Prefill, decode, and storage are distinct costs

Dense prefill over N prompt tokens performs O(N²) attention work. With a KV cache, each autoregressive decode step ordinarily scans O(N) historical keys and values, while KV storage grows O(N). The proposed system principally targets the repeated decode scan and resident-state requirement. It must still disclose the cost of ingesting and indexing the prompt.

T_token = T_model + T_route + T_fetch + T_refine + T_attention

A tree lookup alone does not make end-to-end inference O(log N). Candidate enumeration, misses, transfer, exact attention, and fallback remain in the critical path.

KV capacity for Qwen3.8-27B

Let LA be the global-attention layer count, HKV the KV-head count, dh the head dimension, and b the number of bits stored per K/V scalar:

M_KV(N) = N × L_A × 2(K,V) × H_KV × d_h × b/8
16 × 2 × 4 × 256 × 2 BF16 bytes = 65,536 bytes/token

Quantized-size estimates should be sourced from the exact model artifact used. For orientation, the Unsloth Qwen3.8-27B page publishes multiple quantization footprints. This report does not treat file size as measured runtime memory.

Resident capacity and bytes per token

M_resident = M_weights + M_runtime + M_recurrent + M_hotKV + M_index
B_token = B_weights + B_hotKV + (1 − h) × B_cold_miss

Here h is the hot-block reuse ratio. If each token requires a completely new 12,288-token BF16 set, 0.75 GiB must be promoted per step—about 8.25 GiB/s at 11 tok/s before index and model traffic. That is not a credible sustained SSD miss path. High reuse, compressed transfers, prefetch, and overlap are architectural requirements.

Bandwidth roofline

Using a 13–16 GB checkpoint payload as a proxy with the theoretical 120 GB/s channel gives an ideal 7.5–9.2 backbone-weight passes/s before dequantization, attention, routing, contention, and thermals. This is not a measured Metal roof. A higher output rate requires disclosed and measured MTP/speculative acceptance.

Thermal roofline

A fanless enclosure can sustain less than its short-burst peak. The protocol must report a warm-up period and a sustained run long enough to expose throttling, not only the fastest initial sample.

Ingestion budget

One million tokens must be tokenized, encoded, and indexed. Cache-build time, peak memory, on-disk size, and whether the cache was created on another machine must be reported.

Quality budget

Weight quantization, KV compression, approximate retrieval, positional extension, and fallback policy introduce separate errors. A strong result must evaluate their composition.

4 · Proposed system

A routed-memory hierarchy, not a magic lookup

The system separates logical addressability from physical residency. Cheap, approximate operations operate on a large space; progressively more expensive operations see progressively smaller candidate sets.

Stage 1

Protect a local core

Keep recent tokens, system instructions, structural anchors, and explicitly pinned state resident. These entries are not exposed to retrieval failure.

Stage 2

Generate semantic codes

Use LSH, product quantization, learned block scoring, coarse attention, or a hybrid to map layer/head queries and stored keys into searchable codes.

Stage 3

Resolve code to block and tier

A directory maps sparse codes to KV-block IDs and residency metadata. Judy is one candidate for this stage, not the semantic router itself.

Stage 4

Promote and prefetch

Fetch or reconstruct only selected K/V blocks, exploit reuse, and overlap misses with ongoing model work.

Stage 5

Refine and attend exactly

Re-rank approximate candidates, combine them with the protected core, and run exact attention over the final set.

Stage 6

Widen or fall back

When router confidence is low, expand the budget or use a denser path. Fallback rate is a first-class quality and cost metric.

Three working-set variables

k_c

Coarse candidates returned by code lookup or block scoring.

k_f

Full K/V entries fetched, reconstructed, or promoted.

k_a

Entries retained for the exact attention operation.

These values must be reported separately. A compact exact set does not guarantee low cost if the coarse postings or cold fetch set remain large.

Judy’s narrow role

A Judy array maps discrete keys to values. It does not know which historical tokens are semantically relevant to a transformer query. A semantic projection must therefore come first. Judy’s testable role is as an adaptive radix directory over sparsely populated codes, block IDs, and tier metadata, potentially with efficient incremental insertion and ordered prefix expansion.

query → semantic code → directory → block IDs / tier metadata → exact attention

The directory must be compared with a hash table, adaptive radix tree, sorted flat postings, IVF/PQ lists, and GPU-friendly layouts while holding the router constant. The relevant metric is end-to-end decode, not isolated lookup latency. The broader routed-memory architecture remains viable if Judy loses.

5 · Evidence audit

Related systems support pieces, not the complete claim

Query-aware KV selection and heterogeneous placement predate the original June 2025 article. The defensible contribution here is a systems synthesis, a consumer-UMA evaluation target, and a Judy-specific comparison—not invention of sparse attention or KV retrieval.

What the June 2026 update changed

The June 2026 revision was the paper’s first major evidence update. It added quantization as an orthogonal compression axis and compared the original ideas with RadixAttention, tree-to-sparse-matrix retrieval, hierarchical pruning, and related sparse-attention work. Version 2.0 preserves that historical step but retracts the old implication that “industry convergence” directly validated Judy arrays. Prefix reuse, hierarchical search, compression, and semantic KV retrieval support different parts of the broader memory-routing thesis.

Closest pipeline match

ParisKV

ParisKV combines collision-based candidate retrieval, low-bit approximate inner-product reranking, full KV in pinned CPU memory, and on-demand fetching through CUDA unified virtual addressing. Its paper reports million-token scaling and up to 2.8× peak decode throughput across batch-size sweeps within full attention’s runnable 64K–256K range.

This closely matches the route–rerank–offload–fetch pipeline. It does not validate Judy, Metal, a fanless MacBook, or a 24 GB total-memory configuration. Paper

Native routing and adjacent evidence

Qwen QSA

The official Flash-Next explanation reports up to 7.6× prefill-kernel and 4.9× decode-kernel speedups at one million tokens. This validates learned query-aware block selection in that architecture, not the present end-to-end target.

SeerAttention and MoBA

SeerAttention learns block gates, while MoBA applies MoE-style top-K routing to context blocks. Both support the router analogy but require model adaptation or continued training.

KTransformers

KTransformers supports heterogeneous active parameter and memory working sets. Its documented one-million-token example uses a 24 GB GPU plus roughly 145 GB of host KV memory, not a 24 GB total laptop.

RadixAttention and HiCache

SGLang uses radix trees for exact prefix reuse and tiers KV through accelerator, host, and storage. It does not discover semantically relevant tokens inside one sequence.

TurboQuant

TurboQuant reports roughly three-bit KV representations while preserving quality in its evaluated models and tasks. It reduces the size of each stored item; routing reduces how many items are touched. The axes are complementary, but universal zero-loss behavior is not assumed.

6 · Preregistration

Hypotheses and comparison baselines

H1 · Capacity

A named 3-bit Qwen3.8-27B artifact, runtime state, router, protected core, and active KV set can remain below a predeclared resident-memory ceiling derived from measured idle availability, with swap disabled or zero swap activity.

H2 · Context-speed retention

After a reusable prompt cache is built, one-million-token logical-context decode retains at least 80% of the same machine’s 32K routed-context speed under thermal steady state. The percentage is primary; absolute tok/s is reported.

H3 · Quality

Routed inference remains within one absolute percentage point of the same dense, quantized reference on declared RULER and LongBench tasks, below 1% relative perplexity increase on named corpora, and above a declared attention recall threshold where dense inspection is available.

H4 · Judy contribution

With semantic codes and candidate budgets held constant, the Judy directory improves a declared end-to-end metric—memory, update cost, p95 lookup plus enumeration, or decode latency— versus at least four alternative layouts.

H5 · Sustained operation

Throughput, latency, and memory remain within declared bounds during a minimum 30-minute generation workload after warm-up.

Stretch target, not primary hypothesis

11–12 effective output tok/s is retained as an aspirational result only if multi-token prediction or speculation is enabled and fully disclosed. The report must separately show raw model passes per second, proposed tokens, accepted tokens, and final output tokens per second. Without such a mechanism, the base-M4 bandwidth roofline makes this target aggressive.

7 · Evaluation

Reproducible experimental protocol

Phase A

Freeze the platform

Publish device SKU, OS, ambient temperature, power state, runtime and model hashes, Metal settings, quantization, YaRN, KV precision, MTP/speculation, idle memory, and swap policy.

Phase B

Build and account for the cache

Measure tokenization, prefill, semantic-code generation, directory build, peak memory, cold-state size, SSD writes, and cache reuse. State whether every step occurred locally.

Phase C

Sweep context and budget

Test 32K, 128K, 262K, 512K, and 1M logical contexts against 2K, 8K, 12K, and 32K exact-attention budgets, plus adaptive widening. Record kc, kf, and ka separately.

Phase D

Measure the whole path

Report TTFT, cache-build time, p50/p95 decode latency, output tok/s, model passes/s, resident memory, swap, cold reads, bytes fetched, hit ratio, reuse distance, index updates, and fallback rate.

Phase E

Test quality adversarially

Include declared RULER and LongBench subsets, single- and multi-hop needles, multi-key aggregation, code-repository questions, perplexity, long generation, and deliberately misleading semantic neighbors.

Phase F

Run to thermal steady state

Warm the system, then run at least 30 minutes. Publish throughput and latency over time rather than one aggregate, and record thermal pressure or frequency information exposed by the operating system.

Quality gates

“99% quality” is not a standalone metric. The following gates bind the claim to a named dense, quantized reference:

  • • No more than one absolute percentage point average loss on the declared long-context task suite.
  • • Less than 1% relative perplexity increase on named corpora.
  • • At least 99% attention-mass recall where dense attention can be inspected, reported by layer/head and not only as a global mean.
  • • Separate results for retrieval, multi-hop reasoning, code, adversarial needles, and long generation.
  • • Fallback rate, widening distribution, and worst-case failures reported alongside averages.

Directory ablation

The Judy comparison holds the semantic router, candidates, memory tier, and block order constant. Compare lookup plus enumeration latency, insert/update cost, memory per posting, cache misses, cold-read amplification, and end-to-end decode against a flat hash table, adaptive radix tree, sorted postings, IVF/PQ list representation, and one GPU-friendly layout.

Reproducibility package

A defensible release includes source code, build instructions, model and runtime hashes, configuration files, prompt manifests, cache schema, raw measurements, analysis scripts, failure logs, and a machine-readable environment report. If licensing prevents redistribution of model artifacts, publish exact immutable identifiers and acquisition instructions.

Research program inherited from the original roadmap

Phase A

Router and directory shakedown

Prove candidate recall, cache accounting, incremental insertion, and controlled Judy-versus-alternatives ablation on the smaller model ladder.

Phase B

Metal tiered-KV path

Integrate unified-memory hot state, compressed cold pages, prefetch, and exact accelerator attention; then attempt the 27B Air benchmark.

Phase C

Model/runtime co-design

Revisit the other original branches—structured positional representations and Judy-inspired sparse masks—only where training and hardware-native layouts justify them.

9 · Limitations

Threats to validity

Attention is layer-dependent

A single global semantic index may not preserve the targets used by every layer and head. Per-layer codes increase index and build cost.

Addressable is not understood

Successfully fetching a token does not prove the model can reason over it at one-million-token positional extension.

Errors compose

Low-bit weights, low-bit KV, approximate search, pruning, and YaRN may interact nonlinearly.

The dense oracle differs in hardware

A one-million-token dense reference may require another machine, introducing runtime and numerical differences.

SSD endurance and latency matter

Repeated cache construction or high miss traffic can cause write amplification, latency spikes, and device wear.

Flash-Next is not the target model

Native QSA results cannot be transferred numerically to a retrofit 27B model, Metal runtime, or consumer thermal envelope.

Judy may be the wrong directory

Modern vector-search, flat postings, or GPU-oriented layouts may outperform a pointer-rich CPU structure. A negative Judy result does not falsify the larger routed-memory thesis.

10 · Conclusion

A narrower claim, and a stronger experiment

Judy arrays and attention still come from different eras of computer science and are optimized for different hardware. The original conclusion therefore survives: the path is not simple fusion, but inspired adaptation grounded in algorithms, architecture, and physical memory behavior.

The defensible implementation thesis is narrower than “Judy arrays solve attention.” Future inference systems may virtualize both parameters and context: large state remains addressable while only a query-dependent working set becomes active.

Quantization reduces the physical size of state. Expert routing reduces active parameter work. KV routing attempts to reduce active memory and attention work. Existing systems demonstrate important pieces of this stack, while Flash-Next shows that routing can become part of model architecture.

The fanless 24 GB MacBook Air is not evidence that the target already works. It is the deliberately constrained instrument chosen to test whether logical context can be decoupled from resident context without hiding the cost elsewhere.

The Judy choice, difficult-task recall, storage behavior, sustained speed, and one-million-token Apple result remain the experiment.
