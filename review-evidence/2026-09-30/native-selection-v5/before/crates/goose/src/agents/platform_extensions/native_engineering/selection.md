Native engineering selection policy v4

Use native operations when they replace work. Keep the ordinary developer workflow for simple textual changes; tools are not a checklist.

- For a source-level symbol rename, prefer one `lsp_query` action=rename with path, symbol, new_name and the intended scope directory. It synchronizes every nonignored language file in a bounded scope, including unopened consumers, and returns a complete edit preview plus plan_id. Inspect public/wire keys, aliases and unrelated symbols. If the plan fits the request, apply it once with `safe_edit_and_test` plan_id and a relevant test/type-check command. Do not manually recreate the same edits or reread every proposed target. Scope coverage does not establish coverage outside that directory. Unsupported/oversized/unsafe plans require ordinary edits; never force a global text replacement.
- For custom multi-file changes, gather only needed context with `hashline_edit` read_many. Copy snapshot_id and compact line anchors into `safe_edit_and_test` files to apply the whole batch and check it once. Use hashline_edit edit_many when checks need a later step. All guards bind the full preimage internally. Reconcile stale changes; never bypass a guard. Use write for new files.
- Use `ast_search` presets (functions/classes/calls plus an exact name) for structural discovery obscured by comments/strings. AST matches syntax, not bindings. Use `lsp_query` references/definition with a declaration's qualified symbol for alias/shadowing questions; inspect ambiguity, partial results and pagination. Servers start on demand and are reused. For host-configured languages, call LSP directly: no shell prerequisite checks or searches of host bundles/server executables are needed. An unavailable response is sufficient evidence to fall back. Unsupported tools require bounded local alternatives, not installation or repeated retries.
- Add appropriate behavior/regression tests and run necessary checks after relevant changes. Reuse current results and successful checks while inputs are unchanged. Avoid routine semantic queries, duplicate reads or checks after success. Receipts prove only the checks that ran; unversioned diagnostics do not prove freshness. Respect normal scope and permissions. No OMP or separate model is involved.
