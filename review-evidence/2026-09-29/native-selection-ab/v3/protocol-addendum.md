# Protocol v3 — scoped local authentication transport

V1 had seven pre-inference Keychain failures, preserved separately; zero model requests. V2 was never launched: automatic approval review rejected passing a live OAuth token to Goose because its tools could access the environment. V3 does not perform that rejected action.

The real OAuth credential remains solely in the parent process, obtained with the normal connector and validated with the production session endpoint before each row. The copied connector returns a random, seven-minute localhost capability only inside Goose. The capability is restricted to at most 60 POST requests to /desktop/v1/chat/completions, is rotated/revoked each row, and cannot retrieve OAuth credentials or access other endpoints. A fixed localhost proxy substitutes the parent OAuth header server-side; the existing production router still authenticates it. Desktop UI authentication remains unchanged. A local mock test verifies scope, expiry, revocation, budget and response non-disclosure using fake credentials. No real OAuth token or API key is injected into the app/Goose/tool environment or persisted by the harness.

Same Rust binaries, Electron app, runtime language servers, fixture/oracle source, 12-row schedule, native-on/Jev-off/Axwise-off settings, timing, scoring and filesystem confinement as the original protocol. This controls coding-loop comparison but is not a production Keychain-compatibility test. Every row preflights both confinement and the capability-returning auth command before model inference. The batch stops immediately on a zero-model-request row. No model-trial retries.
