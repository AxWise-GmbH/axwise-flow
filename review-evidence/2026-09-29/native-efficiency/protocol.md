# Native efficiency screening protocol

Frozen before inference: three configurations × four synthetic TypeScript tasks, exactly 12 model trials. Default Goose uses the preserved previous binary with native off. Previous uses the same binary with native on. Candidate uses the optimized binary with native on. Jev/Axwise off; developer/todo, no Code Mode; legacy loop; Gemini 3.8 Flash, desktop default reasoning effort. Rust debug profile and features match across builds. Actual Electron Settings and Send, fresh Git repositories/profiles, counterbalanced arm order, no task-specific tool instructions or forced AST/LSP calls.

Tasks: invoice boundaries, asynchronous router handlers, typed context rename, and a larger context-reference graph with eight additional consumers and 24 unrelated same-name types. Independent behavior, compiler, public tests, regression tests and mutation detection determine correctness; immutable inputs/Git metadata and unexpected files are checked. Offline calibration rejects every seeded defect and accepts each known-correct solution.

Timing is UI Send through terminal response, including any parent credential refresh during a trial. Setup and independent evaluation excluded. 360-second task timeout; normal Goose action default; 60-call local model capability. No model trial is discarded, retried or replaced. No speed comparison treats an error or incorrect result as successful completion. A task cap remains a limitation, especially for the larger task.

Keychain unlocked interactively through the hidden system prompt. No password retained in files, commands, environment, benchmark profiles or credentials handed to Goose. The normal connector reads/refreshes OAuth in the parent, checked at most every 20 seconds during model requests; same account required. Confined Goose receives only an expiring model-only localhost capability. Parent refresh failures fail closed, with no model HTTP retry. The copied Electron app can separately require a native Keychain item permission. Two pre-inference renderer failures are preserved; the startup stack showed Keychain access waiting. Computer Use cannot control SecurityAgent, so local user approval was requested.

Identical backend/child filesystem boundary per arm, with 13 probes per row. Electron, network and IPC are not completely isolated. No installation or production app replacement. Provider/cache load is uncontrolled. Four examples/build are screening evidence; they cannot establish a general reliability or speed improvement.

Targets: no observed correctness regression, intact deterministic safeguards, no simple-task slowdown, and approximately 20% lower medium/complex completion time against both reference configurations. These are targets, not predicted results. Retain all failures and inspect adoption/call counts as explanatory evidence, not success criteria.
