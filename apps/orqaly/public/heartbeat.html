How to read these results

Each row sends the same prompt to two paths. Orqanix uses its application workflow, including source retrieval and tools where applicable. Direct model sends the prompt to Gemini directly. Extra orchestration can add time; it is useful only when the resulting quality or capability warrants it.

Completed means an answer arrived. Checks passed/failed reports task checks separately. Jev: supported/concerns is an advisory assessment of the requested outcome and evidence, not a probability of success. Execution failed after… is time spent before an execution error, not the time needed for a successful answer. Select the row’s ⓘ button to inspect the prompt, checks and output links.

For Message, Search, Research and Plan, elapsed time measures the request through its final response; subsequent benchmark judging is excluded. The Orqanix cloud Coding arm is retired and reports unavailable; the direct-model comparator still includes fixture tests and Jev review. Native Goose engineering has a separate benchmark. Historical receipts retain their original method and source revision. This does not test the packaged desktop. Plan evaluates a generated document, not execution of its steps.

Tokens are shown only when captured by the workflow. Not captured means instrumentation is missing, not zero usage. No cost or token-saving conclusion is possible for those rows. Model identity and hashes are available under each row’s ⓘ button.

These are prompt-level workflow observations. Earlier component benchmarks measure their own workloads and should be compared only when prompt, model, tools and timing boundaries match. History retains failures and earlier evaluator revisions; each run identifies its source revision.
