# Orqaly workflow v2 transition table

`transition(snapshot, event)` is the only component allowed to decide successor stages, retry attempts, approval effects, recovery behavior, or terminal run status. PostgreSQL applies the returned plan generically with tenant, hash, row-version, uniqueness, and lease checks.

The **Cell** column is a stable identifier shared with the mechanically checked table in
`lib/workflow-v2/transition-table.js`. A row may narrow one typed event to a deterministic
branch; together the rows cover every typed event and every eligible branch.

| Cell | Eligible run / stage / attempt | Typed event | Guard | Atomic state decision | Outbox decision |
|---|---|---|---|---|---|
| `run-requested` | `requested`; empty run | `RunRequested` | tenant/run/owner/mode/request hashes match; seven stable stage IDs are distinct | Create compile → Gate 1 → research → planning → Gate 2 plus evaluation and synthesis; create compile attempt 1 | Dispatch `CompileScopeV2` with the persisted operation ID |
| `capability-run-requested` | `requested`; empty explicit `capability_work_v1` run | `CapabilityRunRequested` | Explicit owner action accepts the exact Google scope-compiler disclosure; tenant/user/profile/request/input hashes match; disabled by default | Create only compile scope and scope approval, preserving the legacy Goal graph; no transcript bytes in compilation | Dispatch only `CompileScopeV2` |
| `capability-scope-approved` | `awaiting_gate_1`; capability Gate 1 `awaiting_approval` | `CapabilityScopeApproved` | Exact immutable current scope, owner, input hash and affirmative compatibility review | Record scope approval; settle gate; become `awaiting_capability_input` | none; approval is not Google processing consent |
| `capability-activity-requested` | Explicit capability work only; `awaiting_capability_input`, `completed`, or `failed`; no unsettled stage | `CapabilityActivityRequested` | Same owner/run/profile and exact approved scope; fresh stage/attempt/operation IDs; current row version; same-run completed source; paid input requires a separately confirmed Google disclosure bound to complete input/owner/operation | Append one bounded execution stage on the same ledger; retain previous immutable outputs; become `running`; never reopen a legacy Goal | Dispatch only the exact owner-requested corpus admission, analysis, or simulation operation |

| `approval-granted-plan` | `awaiting_gate_2`; Gate 2 `awaiting_approval` | `ApprovalGranted` | kind `plan`; exact producer artifact/input hashes; fresh idempotency key; exact dependency-root inputs | Persist approval; complete gate; create attempts for dependency-free execution roots | Dispatch all ready root execution stages |

Invariants:

- Capability work is disabled by default. Its migration 025 and database-level owner-event enforcement are not yet implemented or verified; local typed transitions do not establish database authorization. In particular, the old generic worker-callable RPC must not be allowed to bypass owner-only capability events before activation.
- Capability scope compilation uses the existing lifecycle/lease rules. A capability admission completion returns to `awaiting_capability_input`; a paid completion settles the work as `completed` and updates only that capability work item's latest-result pointer while preserving every prior stage output. Capability completion creates no successor and no export side effect. Paid failures never create automatic retries; a fresh explicit review/consent is required. Supplied corpus admission is model-free and does not grant later processing consent.

- Simple and Advanced submit the same command/event contracts. `mode` affects projection only.
- AxWise completion events carry immutable facts, never a successor-stage instruction.
- Polling, heartbeats, lost responses, and deployment rotation never create new durable identity.
- Only a terminal failed attempt may authorize attempt N+1.
- Approvals bind the exact immutable artifact hash and canonical input hash.
- Evidence readiness is deterministic: unresolved applicable blocking legal/safety evidence blocks; only nonblocking gaps permit `completed_with_evidence_gaps`.
- Blocked research still produces a safe remediation Markdown artifact, but never enters planning, Gate 2, or execution and never changes readiness or authorizes launch.
- Tenant/status/capability filtering occurs before agent ranking/limiting; an unrelated agent is never used as a fallback for a required role.
- Execution, evaluation, final repair, and blocked-report cognition all reuse the durable `SynthesizeArtifactV1` operation boundary with a strict purpose discriminator; Orqaly alone chooses successors.
- Outbox idempotency keys are stable per operation and command kind, so replay cannot duplicate downstream work.
