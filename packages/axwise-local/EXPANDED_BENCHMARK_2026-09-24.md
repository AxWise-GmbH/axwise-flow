# Expanded local Axwise benchmark — 24 September 2026

## Outcome and scope

The final standard fixture passed all nine deterministic integration, lineage and
revision checks in one fresh run. The deep fixture also passed all nine checks,
but **across explicitly recorded resumptions and a persona-context fix**, not as
one uninterrupted run. Earlier failures remain in the evidence below.

Both additive revisions retained every prior PRD item and its stable identity,
preserved the original saved file, and added exactly one requested owner
acceptance condition. Both persona discussions received the complete, exact
selected PRD and distinguished existing requirements from new suggestions.
Mixed legacy analysis plus discovery/market references worked without a host
retry for a reference conflict.

This is an **explicit packaged-MCP benchmark**, not an Electron conversation,
natural Goose routing test, vanilla comparison, randomized Axwise on/off trial,
or release approval. Those desktop measurements must be assessed separately.
No publishing, upload, deployment, installed-app replacement or permissions
change was part of this benchmark.

Synthetic interviews remain usable inputs to discovery and product synthesis.
The benchmark did not change that policy or reduce their role. Existing source
identities and labels were preserved. Quotation checks distinguish exact supplied
content from new proposals; they do not prohibit useful compatible enhancements.

## Method and build identity

Runner: `scripts/benchmark-axwise-expanded.mjs`; offline tests:
`scripts/benchmark-axwise-expanded.test.mjs`. Default invocation is a dry run
without authentication, file writes, network or inference. Live execution is
explicit and uses the existing packaged connector authentication through
`connect`, plus `readSavedArtifact` and `readSavedResult` from the existing
benchmark utilities.

- Fixture-order seed: `4afe72401387a909`; initial order was repair, then pantry.
  This only shuffles fixture order, not an on/off treatment comparison.
- Each fresh fixture uses isolated temporary state. Resumptions reuse only
  hash-verified exact saved references in the original fixture state directory.
- Input, reference, immutable JSON/Markdown descriptors, output, model-stage
  usage, timing and validation outcomes are saved per stage.
- No automatic harness retry. Runtime generation/review/repair calls remain
  visible. Failed dependencies are recorded as skipped, not invented successes.
- Stage wall time runs from preparing the explicit tool request through its
  response, saved-file verification and deterministic checks. It excludes
  connection setup and does not include Goose selection or final-summary spans.
- Model-call counts include generation, review, repair and simulation calls.
  Instrumented inference time sums reported model stages; parallel deep interview
  calls mean this is not always the same as elapsed model time.
- Desktop benchmarking ran concurrently against the shared gateway. Provider
  load and caching were not controlled. Timing is exploratory, not a benchmark
  SLA or proof of superiority.

## Preserved failures, corrections and resumptions

Exactly **20 explicit MCP attempts** were made: 18 eventually successful stage
artifacts, one initial standard discovery failure, and one rejected persona
attempt. Model inference totaled 44 calls, including the two calls spent on the
failed discovery attempt. No successful artifact was regenerated merely to
obtain a better benchmark result.

1. **Initial standard discovery — real failure, 13.172 seconds, two model calls.**
   The model quoted the owner specification exactly but assigned
   `simulation_hypothesis` to a `supplied_document` source. The source-kind
   contract requires `source_statement` for an exact quotation of that supplied
   document; this labels attribution, not proof that fictional content is true.
   Generation and repair made the same mistake. The diagnostic was only
   `INVALID_CANDIDATE_SCHEMA`, and the tool returned `VALIDATION_FAILED`.
   Its descendants were skipped. Guidance/diagnostics were corrected without
   weakening the validator or changing the fixture's provenance. The later fresh
   standard run passed with the identical fixture.

2. **Deep simulation — harness false failure, original artifact retained.**
   The first check incorrectly expected two total transcript turns per document.
   Actual documents correctly contained two interviewer questions plus two
   participant answers. The check now counts participant answers and validates
   question identities separately; a regression covers missing answers. Four
   participants and eight answers had completed successfully. No simulation
   inference was repeated.

3. **Deep analysis — harness false failure, original artifact retained.**
   The first check compared quote offsets/IDs directly to simulation documents.
   Analysis intentionally constructs a normalized corpus with new document IDs
   and offsets. The corrected check verifies simulation text against
   `resolvedInput.transcripts`, follows `provenance.sourceCatalogue`, and checks
   exact normalized UTF-8 spans, participant identity and turn role. All eight
   participant quotes matched. No analysis inference was repeated.

4. **Deep persona discussion — real input failure, 0.359 seconds, zero model calls.**
   The exact PRD reached the context resolver, but its `sources` entries were
   metadata-only citation catalogue rows, not full text-bearing evidence sources.
   Parsing those rows as full evidence rejected the input. The repair preserves
   the entire selected PRD and its catalogue as document context; only sources
   containing actual text can become quote passages. Malformed full sources and
   cohort sources remain strictly validated. The exact saved cohort/PRD request
   then passed in 6.943 seconds on the final resources.

5. **Per-stage cache normalization — harness correction, no inference repeated.**
   Runtime model-stage counters reside at the stage top level rather than always
   under `usage`. The reader now supports the actual shape. This changed no cache
   conclusion: all relevant counters in retained runs were unavailable.

Resumed reports clearly label their source report and `freshFullRun: false`.
Reused artifacts are rechecked rather than trusting an earlier pass/fail label.
Original report files were not rewritten to remove failed attempts or false
failure labels.

## Semantic audit

### What worked

- Deep analysis produced substantive contrasts between checklist-driven and
  floor-interrupted coordinators, and between digital scheduling certainty and
  phone-assisted accessibility. It retained manual approval and the capacity cap.
- Market outputs attributed the selected publisher excerpts precisely and did
  not turn documented competitor features into evidence of demand for the pilots.
- Both initial PRDs kept the core pilot scope, exclusions and numeric system
  targets. The deep PRD added compatible proposals such as a timed rollback and
  phone-intake parity monitoring, not a new product direction.
- Standard persona feedback acknowledged the existing PRD and proposed a
  workload-count indicator beside the manual-assignment options. Deep persona
  feedback acknowledged existing locking, intake and publishing, then suggested
  a specifically timed soft reservation while taking a phone call. Both were
  framed as enhancements, not quotations from an unavailable document.
- Additive revisions preserved **26/26 standard** and **28/28 deep** old items,
  exact content, section order and stable IDs. Each appended exactly one owner
  acceptance condition with no invented finding/source attribution. Original
  saved JSON hashes stayed unchanged. The standard addition was the exact
  duplicate-email warning scenario; the deep addition was the seventh-volunteer
  capacity warning. These were explicit MCP regressions, not the separate
  original desktop edit rerun.

### Remaining caveats

- The standard initial PRD partly conflated **five-second system propagation
  after an update** with **a technician acting within five seconds after work
  completion**, then proposed a human task-time metric. The core system-latency
  requirement remains, but these are different measurements and should be
  clarified. This is an unintended operational expectation, not a different
  product direction; the additive revision preserved it rather than causing it.
- The same PRD mixes a universal integration-test latency acceptance condition
  with percentile-based pilot metrics. These may be useful separate test and
  operating targets, but their relationship needs explicit wording rather than
  assuming they are interchangeable.
- A persona's short-lived reservation suggestion is an implementation refinement
  of a PRD that already mentions reservation/locking. It should not be read as
  proof that the whole feature was absent.
- Publisher evidence was deliberately small and relevant to one capability per
  case. This is not broad market discovery, statistical research or a comparison
  of retrieval systems.
- Deterministic success and a passed model review do not prove complete semantic
  correctness. The caveats above remain even though all final structural checks
  passed.

## Measured latency opportunity

Both analyses required four calls: generation, review, repair and final review.
In both operation journals, the first reviewer rejected `evidence_gaps` because
the initial artifact had `gaps: []` while its limitations acknowledged unmeasured
operational baselines. Repair added concrete next checks, then review passed.
This is a reproducible generator/reviewer alignment issue, not a routing delay.

Improve first-pass structured gap generation from already acknowledged unknowns
without weakening the reviewer or restricting synthetic input use. The deep PRD
also required generation, repair and final review. Large repeated contexts matter
too: the deep persona and revision returned aggregate input counts of 29,866 and
42,943 tokens respectively across their two calls. Their observed wall times were
still about seven seconds; these counts alone do not establish a latency cause.
